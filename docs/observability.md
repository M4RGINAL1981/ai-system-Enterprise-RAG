# Безопасность, наблюдаемость и устойчивость Enterprise-RAG

Документ фиксирует архитектурные требования и проектные решения в области информационной безопасности, протоколирования и контроля качества работы ИИ-системы.

---

## 1. Информационная безопасность и защита данных

### Аутентификация и авторизация:
* **Защита периметра:** Доступ к любым эндпоинтам прикладного контура (включая инференс `/predict`) закрыт для неавторизованных пользователей.
* **Механизм передачи:** Взаимодействие со шлюзом осуществляется строго по протоколу HTTPS. Клиент обязан передавать статический токен в заголовке запроса: `X-API-Key: <secret_token>`. Валидация ключа происходит на уровне Middleware в FastAPI до передачи запроса в контур ИИ.

### Защита от DoS/DDoS и инфраструктурных сбоев:
* **Payload Size Limit:** На уровне API Gateway (FastAPI/Nginx) установлено жесткое ограничение на размер входящего JSON-пакета — **до 2 Мб**. Это предотвращает отправку гигантских текстов, способных перегрузить эмбеддер.
* **Тайм-ауты (Timeouts):** Для защиты пула соединений выставлен лимит ожидания ответа от векторной БД — **200 мс**, от сервиса генерации LLM — **8000 мс**. При превышении лимитов возвращается статус `504 Gateway Timeout`.

### Комплаенс (Соответствие 152-ФЗ «О персональных данных»):
* **Приватность запросов:** Корпоративные регламенты не содержат персональных данных, однако пользователи могут случайно или намеренно ввести их в окне вопроса (ФИО, телефоны, паспорта).
* **Маскирование:** Перед отправкой текста в контур эмбеддера и во внешнюю LLM, модуль `app.postprocessor` (Guardrails) производит автоматическое обезличивание и маскирование персональных данных с помощью регулярных выражений или легковесных Named Entity Recognition (NER) моделей. В логи персональные данные не попадают.

## 2. Наблюдаемость (Observability) и аудит

### Структурированное логирование (JSON Logging):
Каждый входящий запрос и результат его обработки атомарно записывается в стандартный поток вывода (`stdout`) в формате структурированного JSON. Это позволяет системам сбора логов (Loki/Fluentd) мгновенно индексировать записи.

**Пример лога успешного инференса (200 OK):**
```json
{
  "timestamp": "2026-10-06T12:00:05Z",
  "level": "INFO",
  "request_id": "4a7c1b5e-8d9e-4b2a-8d1c-9e2b1a4c8d3e",
  "session_id": "user_session_92a1",
  "latency_ms": 1150.4,
  "status": 200,
  "model_version": "bge-m3_llama-3-8b-instruct",
  "retrieval_confidence": 0.89,
  "manual_review_required": false
}
```

**Пример лога при срабатывании Fallback-сценария (Низкая уверенность поиска):**
```json
{
  "timestamp": "2026-10-06T12:05:21Z",
  "level": "WARNING",
  "request_id": "f82b13c2-11da-4c3e-9081-62283cb73aa1",
  "session_id": "user_session_92a1",
  "latency_ms": 45.2,
  "status": 200,
  "model_version": "bge-m3_llama-3-8b-instruct",
  "retrieval_confidence": 0.21,
  "manual_review_required": true
}
```

### Технические и ML-метрики (Prometheus):
Система собирает и непрерывно отдает Prometheus следующие метрики:
1. `http_requests_total` (Counter) — Счетчик запросов по кодам ответа (`200`, `400`, `500`).
2. `http_request_duration_seconds` (Histogram) — Полное время обработки запроса пользователем.
3. `rag_retrieval_duration_seconds` (Histogram) — Чистое время поиска в векторной БД Qdrant/pgvector.
4. `rag_retrieval_confidence_score` (Gauge) — Уровень релевантности найденного контекста для мониторинга качества работы ретривера.

### Контроль дрейфа данных (Data & Concept Drift):
* **Проблема дрейфа в RAG:** Со временем пользователи могут начать задавать вопросы по совершенно новым темам, которых еще нет в загруженных регламентах, либо язык общения сотрудников изменится (появится новый сленг/аббревиатуры). Из-за этого качество поиска ухудшится.
* **Решение:** Логи всех входящих запросов (`question`) сохраняются в реляционную БД. Раз в неделю запускается offline-пайплайн на базе библиотеки **Evidently**. Он строит эмбеддинги новых вопросов и сравнивает их статистическое распределение с историческим эталоном (Baseline) с использованием теста Колмогорова-Смирнова. При обнаружении значительного расхождения (дрейфа данных) система отправляет алерт администраторам о необходимости дообучения эмбеддера или расширения базы знаний новыми документами.
