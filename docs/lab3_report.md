# Отчет по лабораторной работе № 3
**Тема:** Реализация программного компонента AI-системы «Enterprise RAG»

## 1. Назначение компонента и место в архитектуре
Реализован компонент семантического поиска и генерации ответа по корпоративным регламентам.
* **Вход:** Текстовый вопрос сотрудника (`PredictionRequest`).
* **Выход:** Сгенерированный ответ, список источников, оценка уверенности и флаг передачи человеку (`PredictionResponse`).

## 2. Разделение ответственности
1. `app/api/schemas.py`: Pydantic-контракты входа и выхода.
2. `app/ml/preprocessing.py`: Очистка текста от мусора, нормализация, маскирование ПДН (email, телефоны).
3. `app/ml/inference.py`: Локальный семантический поиск на базе TF-IDF и косинусного сходства по локальной базе знаний.
4. `app/services/prediction.py`: Прикладное бизнес-правило (при `score < 0.4` выставляется `manual_review_required = True`).

## 3. Результаты тестирования
Запуск модульных тестов выполнен командой `python -m pytest -q`.
Проведено 4 независимых теста:
1. `test_predict_success` — корректный поиск ответа по регламенту отпусков (PASSED).
2. `test_predict_different_query` — поиск по теме ИТ-поддержки (PASSED).
3. `test_predict_low_confidence_fallback` — обработка нерелевантного вопроса с передачей оператору (PASSED).
4. `test_predict_invalid_input` — отсечение короче 5 символов через ValidationError (PASSED).

## 4. Вывод
В лабораторной работе № 3 для проекта «Enterprise RAG» реализован компонент поиска по регламентам. Он принимает `PredictionRequest` и возвращает `PredictionResponse`. Интеллектуальная функция реализована с помощью TF-IDF векторайзера; прикладные правила выполняются в модуле `app.services.prediction`. На тестовых входах продемонстрированы успешный поиск, переадресация оператору и обработка ошибки валидации. Компонент полностью соответствует архитектуре ЛР № 2. Цель работы достигнута.
