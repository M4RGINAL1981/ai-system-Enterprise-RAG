# Model Card: Enterprise RAG Depository Assistant (`v0.1.0`)

## 1. Model Details
* **Разработчик:** Студент кафедры ИИ / АС, ЮУрГУ (2026)
* **Версия и тип:** `v0.1.0` (`hybrid-rag-v2`), двухконтурная система информационного поиска (Hybrid Information Retrieval)
* **Архитектура:**
  * *Основной контур (Dense Retrieval):* мультиязычный трансформер-энкодер `intfloat/multilingual-e5-small` (размерность эмбеддингов 384, косинусная близость) + векторная база данных `Qdrant`.
  * *Резервный контур (Fallback Sparse Retrieval):* конвейер `ColumnTransformer` (`TfidfVectorizer` до 3000 признаков + `OneHotEncoder` для групп доступа), сохранённый в `artifacts/preprocessor.joblib`.
* **Лицензия и воспроизводимость:** Исходный код под лицензией MIT; конвейер данных и артефакты зафиксированы в `dvc.lock` и `MLflow`.

## 2. Intended Use
* **Основное назначение:** Автоматизированный поиск релевантных фрагментов и ссылок на первоисточники (документ, номер страницы, ID чанка) по «Условиям осуществления депозитарной деятельности АО «БКС Банк»» для сотрудников и клиентов-депонентов.
* **Целевые пользователи:** Внутренние специалисты депозитария, служба поддержки клиентов и администраторы базы знаний.
* **Вне области применения (Out-of-Scope):** Система не предназначена для принятия юридически значимых решений без участия человека, проведения финансовых транзакций или ответов на вопросы, не относящиеся к депозитарному регламенту.

## 3. Factors & Data
* **Источник данных:** Типовой клиентский регламент депозитария АО «БКС Банк» (`terms-of-depository-activity-180806.pdf`, 172 страницы).
* **Предобработка и чанкинг:** Текст очищен от персональных данных (маскирование email и телефонов) и разбит на 812 перекрывающихся фрагментов (`chunk_size = 800`, `chunk_overlap = 150`).
* **Разбиение выборок:** 80% (`649` чанков) — обучающая выборка (`train.parquet`), 20% (`163` чанка) — тестовая (`test.parquet`). Обучение TF-IDF выполнено строго на `train` для исключения утечки данных (Data Leakage).
* **Разграничение контекстов:** Фрагменты разделены на группы доступа `client` (стр. 1–89, общие условия) и `staff` (стр. 90–172, анкеты и внутренние формы).

## 4. Metrics & Evaluation
* **Пороги принятия решений (Decision Thresholds):**
  * Для основного поиска (`qdrant_dense`): порог косинусной близости `>= 0.82`.
  * Для резервного поиска (`fallback_tfidf`): порог косинусной близости `>= 0.25`.
* **Бизнес-правило отказоустойчивости (Human-in-the-Loop):** При уверенности ниже заданного порога система не выдумывает ответ, а выставляет флаг `manual_review_required = true` и переводит запрос на оператора.
* **Операционные показатели:**
  * Валидация схемы данных через `Pandera` (0 пропущенных аномалий из 812 чанков).
  * Автоматическое переключение на `fallback_tfidf` при недоступности `Qdrant` с сохранением доступности API (`HTTP 200`).

## 5. Caveats & Limitations
* **Особенности распределения скоров E5:** Модели семейства `multilingual-e5` выдают плотные значения косинусной близости в узком диапазоне (`0.75–0.95`), что требует строгой калибровки порога отсечения (`0.82`).
* **Отсутствие генеративного перефразирования:** В текущей версии `v0.1.0` сервис возвращает верифицированную выдержку из регламента без синтеза текста языковой моделью (что полностью исключает галлюцинации LLM).
* **Актуальность базы знаний:** При обновлении регламента требуется повторный запуск `dvc repro` для переиндексации коллекции в `Qdrant` и обновления `preprocessor.joblib`.
